## 失败、修复与状态

- 首次 `pnpm install --frozen-lockfile` 退出 254：默认 store `/home/agent/.local/share/pnpm` 的目录创建受沙箱限制；附加路径授权尝试仍 254。之后按原命令申请执行权限，默认 store 安装成功且供应链检查通过。**已解决**，没有换缓存、源或执行环境，没有关闭策略。
- 初次 `pnpm runtime:check` 退出 1：清单变化触发 pnpm 依赖状态检查，其默认 store SQLite 无法在当时权限内打开；原路径完成安装后检查成功。**已解决**。
- 浏览器首次独立 HTTP APIRequestContext 未自动发送生产 Secure cookie，得到 401。已显式使用浏览器真实登录签发的会话进行独立 API 请求，保留 Secure/HttpOnly 标志。**验收工具已修复**，生产代码未放宽 cookie。
- 一次早期浏览器严检只记录到未定位 URL 的 404；增加 URL 采集后在 `/pms` 明确定位为 `/favicon.ico`。默认场景最终为 0 个错误，但不能据此抹去已复现的共享缺图标问题。**共享待处理**。
- `/pms/` 登录验收曾因 Next 规范化为 `/pms` 导致工具超时。工具接受这两个等价首页地址，再次运行走完其他断言；保留 [原超时](../docs/work-packages/WP-01/29-browser-basepath.log)。**验收工具已修复**。
- 自查将“已打开的 DB 关闭后请求”升级为全新目录子进程测试，实际复现匿名请求仍先初始化 DB。[修复前失败](../docs/work-packages/WP-01/23-preauth-regression-before.log) → 将无 cookie 拒绝前置 → [修复后成功](../docs/work-packages/WP-01/24-preauth-regression-after.log)，随后全量 81/81。**已解决**。
- Next 构建自动把非 owns 的 `next-env.d.ts` 从 dev 类型路径改为 build 类型路径。每次构建后已恢复起点原文，最终无该文件差异。**未越界交付**。
