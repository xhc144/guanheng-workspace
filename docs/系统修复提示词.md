你是“总管 AI”。你的任务是修复并统一我公司的内部管理系统，方法是：先自己盘点现状，再把工作拆成 20–30 个工作包，每个工作包开一个独立的 git worktree 分支和一个子 AI 并行完成，最后由你复审、合并、验收。子 AI 数量不设上限，按需开启。

## 一、公司背景（决定系统该怎么设计）

- 公司：关衡（关衡软件），专注关务数智化合规管理，产品是关务 / AEO 合规 / 加工贸易管理软件，客户是有进出口业务的制造企业，也做口岸平台类政府项目。
- 业务模式：商机 → 投标（技术标、方案 PPT）→ 签合同 → 实施交付（蓝图、实施、上线、验收）→ 每年收取运维服务费。
- 款项习惯：合同分期收款（首期款、蓝图款、实施款、验收款），一笔款可能多次开票、多次回款；年度服务费到期要续费提醒；项目有多人参与，按点数分提成，常规条件是“收到指定款项后才能发提成”。
- 还在运营：官网、官网上的 99 元投标方案自动生成服务（DeepSeek 改写 + 微信支付待接入）。
- 团队小、懂代码的人少，系统必须：中文界面、双击能启动、出了问题看得懂报错。

## 二、现有系统（都在 E:\项目\03_效率工具 下）

1. 项目经营管理系统（Next.js + SQLite + pnpm）
   - 已在腾讯云 /pms 路径上线，有真实历史总账数据（data/app.db），是目前唯一在真实使用的系统。
   - 已知问题：package.json 里 next、react 等大量依赖写的是 "latest"，任何一次重新安装都可能装到不兼容版本导致构建失败；只能用 IP 访问，没有备案域名；.ai-handoff/ISSUES.md 里 ISSUE-0001 业务术语（“暑期款”“运输款”“千万合同”等疑似听写错误）和提成口径仍未确认；企业微信通知未接。
2. 综合项目管理系统系列（FastAPI + React/Vite，三套并行版本：基础版、DeepSeek版、Kimi版，另有一份重复的“源码包”目录和 zip）
   - 已知问题：整个文件夹从 E:\项目\应用项目 搬到了现在的位置，但各版本的 Python .venv 里还写死旧路径，虚拟环境已经失效，一键启动大概率失败；

## 三、最终目标

1. 以“项目经营管理系统”为唯一主线（它有真实数据和线上环境），不另起新项目。
2. 把“综合项目管理系统 DeepSeek版”里主线缺少、且对关衡有用的功能移植进主线：里程碑/甘特、工时与资源负载、风险与审批、预算与成本利润、客户门户。移植要按主线的技术栈重写，不是把 Python 代码塞进来。
3. 增加关衡特有的模块：商机与投标管理（投标项目、技术标文件、报价、中标/未中标、转合同），以及关务项目实施模板（加工贸易 / AEO 项目的标准阶段和交付物清单）。
4. 综合项目管理系统系列修到“能启动、能登录、文档与实际一致”，然后标记为归档参考版，不再继续开发。
5. 全程不丢、不改坏真实数据：任何涉及 data/app.db 的操作先 pnpm db:backup，子 AI 只用测试库。

## 四、你要怎么做

1. 先盘点：读两个系统的 README、PROJECT_GOAL.md、AGENTS.md、.ai-handoff/、FINAL_STATUS.md，实际运行一次各自的测试和启动，把“真实现状”和“文档声称”对比，写 reports/00-盘点.md。不要相信任何没有命令输出证明的“已完成”。
2. 再拆包：按下面的清单拆成 20–30 个工作包（可以合并或细化，但每个包必须是“数据 + 逻辑 + 接口 + 页面 + 测试”的完整切片，预计至少 30 分钟，改动不少于 5 个文件），写入 tasks/queue.json，字段：id、title、branch、owns（独占路径，不得重叠）、depends_on、brief、done_when、min_minutes。
3. 并行派发：每个包一个 git worktree + 一个子 AI，同时运行 20 个以上。子 AI 完成标准后不准收工，继续补边界测试、错误提示、手机布局和文档，直到连续两轮自查无问题；结束写 reports/<id>.md。
4. 复审：每个包完成后，另开一个只读复审子 AI 检查：是否越权改了别的包的文件、有无占位按钮或假数据、测试是否真实断言、有无写入密钥。
5. 合并：按依赖顺序合并到 integration 分支，每合一个跑一次 pnpm test、pnpm typecheck、pnpm lint、pnpm build；冲突开新的集成子 AI 解决。
6. 验收：integration 全部通过、并用真实浏览器在 375px 和桌面宽度走完“建客户 → 建合同和分期应收 → 开票 → 回款 → 看报表 → 计提成”主流程后，才合并到 main，写 reports/SUMMARY.md。
