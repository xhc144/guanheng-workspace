## 本地使用

在 `systems/project-ops` 执行：

```sh
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm runtime:check
pnpm dev
```

`runtime:check` 成功退出 0；版本不兼容或未读到退出 1；直接调用诊断模块的参数错误退出 2。Node 检查先用普通 JavaScript 执行，因此不兼容 Node 会在加载 TypeScript 前获得中文提示。实际旧 Node 二进制未在本环境安装，拒绝逻辑通过构造版本输入及真实子进程执行启动检查验证，不能称为跨版本实机测试。

开发、构建、生产启动分别在原 `next dev`、`next build`、`next start` 前执行 `pnpm runtime:check`。`test`、`typecheck`、`lint` 及原数据库脚本定义保留。没有为尚未交付的脚本添加虚假入口。WP-06、WP-23、WP-24 不得代改 package 或脚本；如需新增入口，在各自报告申请，由根协调 WP-01 处理。

## 页面与接口

管理员登录后访问 `/runtime-health`，部署设置 basePath 时在其前添加该前缀。页面显示当前版本、已验证版本、中文兼容性结果和北京时间；“重新检查”实际重新请求服务端并更新时间。手机为卡片布局，不依赖横向表格。

`GET /api/runtime-health` 使用现有 `pms_session` 会话，角色在服务端重新读取：

| 场景 | 状态码 | 响应 |
| --- | --- | --- |
| 无会话、伪造/过期/停用会话 | 401 | `{"error":"请先登录"}` |
| 财务、部门负责人、项目人员 | 403 | `{"error":"仅管理员可查看运行诊断"}` |
| 管理员 | 200 | `status`、`checkedAt`、5 项 `checks` |
| 读取发生内部异常 | 500 | 固定中文错误，不回显异常内容 |
| POST 等未实现的写方法 | 405 | Next 路由层拒绝 |

版本状态为 `ok`、`error`、`unknown`；任何未读取项都会使总体状态为 `attention`，不会伪装成功。所有 GET 响应（包括拒绝）均为 `Cache-Control: private, no-store` 和 `Vary: Cookie`。Next 自动 HEAD 复用同一鉴权。

诊断代码只输出 Node/pnpm/Next/React/React DOM 版本及结果。它不读取环境变量值、数据库路径、附件、财务明细，不对外探测。pnpm 版本通过本机固定命令 `pnpm --pm-on-fail=error --offline --version` 读取，5 秒超时，输出限 1024 字节；只接受版本格式，异常和原始输出都不返回。不会安装依赖或自动切换包管理器。

无 cookie 的页面和 API 会在调用共享数据库前拒绝。鉴权复用既有 `getDb()`；携带 cookie 的请求首次初始化 schema 的行为属于主线现有共享地基，本包未修改该逻辑。已存在的数据库上，测试在 `PRAGMA query_only=ON` 下实际调用 GET 并比较 `total_changes()`，验证诊断本身不写数据库。另在全新临时目录的真实子进程验证：匿名 GET 返回 401 且不会创建 data 目录。

不新增表、迁移、业务权限或业务口径。主导航入口交由 WP-24 唯一 owner 注册：管理员专用“运行诊断” → `/runtime-health`。

## 测试与证据

`systems/project-ops/tests/runtime-health.test.ts` 通过原 `pnpm test` 入口自动执行。新增 13 项测试覆盖真实安装版本、诊断时间、兼容/不兼容与预发布输入、异常版本内容过滤、子进程退出码、实际 API 的 401/403/200/500、会话过期/停用/降权、合成 secret 隔离、只读数据库和匿名请求不初始化数据库。

`browser-check.mjs` 是补充验收工具：复制本次 standalone 构建到新建 `/tmp` 目录，使用 4 个合成账号和专用合成数据库，启动本机生产模式实例，验收后停止。它不向已有实例发送请求，不复制项目 data 或真实配置。Playwright 和 Chromium 路径由参数明确提供，未将浏览器测试依赖混入应用清单。

```sh
node --experimental-strip-types docs/work-packages/WP-01/browser-check.mjs <playwright/index.mjs> <chromium路径>
```

可选第四个参数必须与本次构建的 basePath 一致。375/768/1440px 分别检查整页宽度、实际版本卡片、键盘焦点、至少 44px 按钮和刷新后服务端时间变化，并保存临时截图。浏览器登录保持生产 `Secure/HttpOnly` cookie；在本机 HTTP 下，独立 APIRequestContext 检查显式携带刚刚真实登录签发的会话，未改 cookie 安全标志。

同目录各 `.log` 保留实际 cwd、完整命令、时间、完整输出和退出码。早期失败保留，不能以最终成功覆盖历史失败。DB、截图与 standalone 只在 `/tmp`，不提交二进制。
