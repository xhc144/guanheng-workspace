## 权限问题：失败保留与续接修复

首阶段 `b61a356` 的隔离探针退出 1：普通成员调用普通冲销 403，但统一 `write-off` 为 200 且修改回款/新增审计；非成员项目详情也为 200。该候选没有按数据权限通过放行，失败日志继续保留。

根随后明确允许在已 owned 业务路由接回既有动作权限与项目负责人/成员检查，不新增角色、不扩大访问。本次复用 `require_role("finance")`、`require_role("member")`、`require_role("enterprise_admin")` 和既有 `Project.manager_id/ProjectMember`，全局 `auth.py` 及角色等级未改。统一冲销别名、项目列表/详情/汇总/写入和票款读写、幂等命中/冲突重试均检查权限；关联搜索/导出/报表/甘特/工时/附件等旁路也按同一项目范围过滤。

当前相同探针为 **403 / 403 / 404**，回款仍 confirmed、write_off 审计 0，退出 0。新增测试包括访客即使有成员行也拒绝、非成员与无关联财务拒绝、负责人无需成员行、合法成员/财务成员/两级管理员正例、撤销成员后不能重放旧键、幂等唯一约束冲突回滚后再检查权限、事务开始前撤销动作角色、混合批量/导入拒绝零副作用，以及实际文件存在情况下拒绝下载/上传/删除且磁盘和业务表均不变。

`verify_scope.py` 继续冻结全局身份/角色/配置；只允许统一冲销依赖精确变为既有 finance 门槛。完整后端 **195/195** 通过。这是列明路由与场景的验证，仍不等于全部旧业务权限、安全或生产合规验收。
