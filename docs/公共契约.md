## 已存在的稳定边界

- 数据库：Node `DatabaseSync`、整数分；`openDatabase(path)`、`getDb()`、`inTransaction(db, work)`。
- 内部身份：`SessionUser`与Role为ADMIN、FINANCE、DEPARTMENT_MANAGER、PROJECT_MEMBER。`users.role`存在四值CHECK。
- 权限：`customerScopeSql`、`contractScopeSql`、`receivableScopeSql`、`projectScopeSql`、`workItemScopeSql`、`canAccessProject`、`canManageFinance`、`canAccessEntity`。不能只隐藏前端按钮。
- 审计：`writeAudit(db,{userId,action,entityType,entityId,before?,after?,ipAddress?})`。存在审计函数不能证明写入原子；调用它必须在同一业务事务内。
- 财务：`createInvoiceWithAllocations`、`createReceiptWithAllocations`、`voidFinanceRecord`、`getReceivableStatus`、`calculateCommission`。分摊合计必须等于源金额，且不超有效应收；幂等键同键异请求拒绝。
- 研发：`saveWorkItem`、`addWorkLog`、`addWorkComment`。`work_items.type`已有MILESTONE，`work_logs.minutes`为整数；addWorkLog会更新actual_minutes。WP11独占旧work服务/页面，WP12新目录适配，不双写。
- 项目：`saveProjectRecord(db,input)`自带事务。WP17拥有该文件且保持已有调用签名；WP16先在自己的目录实现中标转建，通过共享原子边界调用。
- 日期：`businessDate()`为Asia/Shanghai。估算日期不计入逾期及本月回款。不能把UTC当天或文件日期当真实业务日期。
- 看板：WP10独占reporting.ts；WP20只消费既有DashboardMetrics，不能复制一套财务SQL后产生不同口径。

## G0必须实现的事务契约

保留`inTransaction<T>(db:DatabaseSync, work:()=>T):T`调用签名。顶层用`BEGIN IMMEDIATE`；同一连接上的嵌套调用使用内部安全SAVEPOINT。保存点名只由服务内部生成，不接用户输入。

- 内层成功后外层失败：所有层业务写入和审计一起回滚。
- 内层失败且向上传播：事务完整回滚；明确捕获内层失败时，仅内层保存点回滚，外层可继续，必须测试其明确行为。
- 旧finance、saveProjectRecord、saveWorkItem等自带事务的服务可被统一原子事务包裹，不得出现“cannot start a transaction within a transaction”。
- 同步回调不得跨网络await；外部邮件/企微/生成服务在事务外投递。
- 并发测试须用同一临时文件的不同数据库连接/进程；顺序调用不能当并发证据。

WP07/08/09/14/16等使用这个已验证边界把写入与审计包在一起。WP10提供覆盖清单及独立对账；跨owner缺陷退对应包修复。

## Migration类型与执行责任

G0由WP24冻结类型，WP23唯一实现执行器：

```ts
interface Migration {
  id: string;                 // wp05-001、wp11-001等，不复用已有id
  checksum: string;           // 稳定文本迁移内容的校验和
  up(db: DatabaseSync): void; // 同步；只新增表、字段和必要索引
}
function applyMigrations(
  db: DatabaseSync,
  migrations: readonly Migration[],
): { applied: string[]; skipped: string[] };
```

WP23负责账本、顺序、校验、失败原子回滚、重试和测试工具。WP24负责`lib/schema.ts`/`lib/db.ts`里的唯一启动注册。各域只拥有`lib/<域>/migrations.ts`等本域描述，不编辑公共schema或runner。当前代码没有这个接口，不得提前import。

各域服务入口显式确保本域迁移已应用，测试也用真实runner安装本域描述，因而独立域PR能运行；汇总启动注册由WP24接回。重复ensure必须幂等并在并发时安全；不能捕获“缺表”后返回假空列表。升级先补缺列再建依赖列的索引，不重建或重命名旧财务表、不改旧CHECK、不把未知历史状态映射为新状态。runner必须拒绝计划外破坏性DDL；测试只用合成旧库，不读真实部署库。
