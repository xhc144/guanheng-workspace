# PMS 三版：本地演示启动说明

三个 PMS 是待归档的 FastAPI/React 演示系统，生产主线为 `systems/project-ops`。本说明只介绍 PMS 本地演示。账号和生产安全边界以 [WP03《PMS账号与配置》](../../docs/PMS账号与配置.md) 为准。

## 新电脑准备

在 Windows 安装 Python 3.10+（含 venv、pip）、Node.js 22.12+（含 npm）和浏览器。基础版原锁中的 Vite 需要较新的 Node，因此三版统一按这个 Node 下限检查。安装后重新打开终端，分别运行：

```powershell
python --version
node --version
npm.cmd --version
```

首次安装需要正常访问 Python/npm 软件源；脚本不会自行安装系统运行时。启动时遇到组织执行策略、安全软件或签名限制，请保留错误交给本机管理员审核。脚本不更改执行策略，也不提供绕过参数。

把干净源码放在自己选择的目录；目录可以包含中文和空格，无需放在固定盘符。不要将真实数据库、附件或 `.env*` 放进演示目录。脚本发现版本目录、backend 或 frontend 中存在 `.env*`（`.env.example` 除外）会拒绝，不读取或覆盖它们；当前终端设置了其他 `DATABASE_URL` 或非 development/test 的 `ENVIRONMENT` 也会拒绝。已有配置请保留，改用独立的干净源码和演示终端。

## 启动与安装

在 `systems/pms-suite` 双击对应文件：

- `一键启动-基础版.bat`
- `一键启动-DeepSeek版.bat`（`DeepSeek版/start.bat` 调用同一 helper）
- `一键启动-Kimi版.bat`（`Kimi版/start.ps1` 调用同一 helper）

启动器按自己的文件位置定位，不依赖终端当前目录。默认先检查两个端口，然后创建缺失的隔离 venv，运行 `python -m pip install -r requirements.txt`、`pip check`、`npm ci --no-audit --no-fund` 和 `npm ls --depth=0`。每次启动都重新按原锁核验安装，首次可能较慢；损坏的 `node_modules` 不会被当成已安装。脚本不更新或生成锁文件，不使用旧的 `backend/venv`。

| 版本 | 隔离 Python 目录 | 前端 | 后端健康接口 | 登录接口 |
| --- | --- | --- | --- | --- |
| 基础版 | `基础版/.venv` | `http://127.0.0.1:5180` | `http://127.0.0.1:8100/api/health` | `/api/auth/login` |
| DeepSeek版 | `DeepSeek版/backend/.venv` | `http://127.0.0.1:5182` | `http://127.0.0.1:8102/api/health` | `/api/auth/login` |
| Kimi版 | `Kimi版/backend/.venv` | `http://127.0.0.1:5181` | `http://127.0.0.1:8101/api/v1/health` | `/api/v1/auth/login` |

后端必须返回 HTTP 200 和 JSON `status: ok`，前端必须返回 HTML，才显示“就绪”并尝试打开浏览器。不会把 `/docs` 或任意占用端口的进程当成已启动的本系统。三版均只监听本机回环地址。

也可以在 PowerShell 中运行（先进入自己的 `systems/pms-suite` 目录）：

```powershell
# 安装并保持服务运行；Ctrl+C 停止
.\start-helper.ps1 -Edition Basic -NoBrowser -NoPopup
.\start-helper.ps1 -Edition DeepSeek -NoBrowser -NoPopup
.\start-helper.ps1 -Edition Kimi -NoBrowser -NoPopup

# 只安装，不创建演示库、不启动服务
.\start-helper.ps1 -Edition DeepSeek -InstallOnly -NoBrowser -NoPopup
```

`-Edition` 必填，支持 `Basic`、`DeepSeek`、`Kimi`；`-Component` 默认 `All`，也可选择 `Backend` 或 `Frontend` 分开启动。基础版的 `scripts/start-backend.ps1` 和 `scripts/start-frontend.ps1` 分别调用这两个模式，先等一个窗口安装完成再开另一个。`DeepSeek版/setup.ps1` 是统一的只安装入口；不再支持跳过检查的 `SkipPython/SkipNode`。

同版正在安装时另一次安装会拒绝；对应服务端口被占用时也会拒绝。`-InstallOnly` 同样检查相关端口，避免在运行中的前端上重新安装模块。

## 登录和数据保留

本地演示账号固定为 `admin` / `Admin@123456`，不用尝试其他备用口令。三版均只使用各自 `backend/.demo/demo.db`，不会连接 `app.db`、`pms.db` 或终端传入的其他数据库。已有演示库不会因启动被删除，已有密码不会重置。

基础版、DeepSeek版由其既有启动逻辑幂等补齐演示数据。Kimi 仅在受控演示库文件不存在时执行现有 Alembic 迁移和演示 seed，已有文件只执行 verify；残留或损坏库会明确失败，不自动删除或重建。

统一启动从不调用 Reset。`Kimi版/start.ps1 -ResetDemo` 会拒绝并要求把重置作为单独操作。确有必要清空**虚构演示数据**时，先停止本版全部服务并自行保留需要的数据，再审核显式的重置命令；不要删除数据库来排查登录失败：

```powershell
# DeepSeek 默认是保留已有数据的 Initialize；只有显式 Reset 才清空受控演示库
.\DeepSeek版\reset-demo.ps1 -Action Reset -Confirm
# Kimi 默认 Prepare：新库迁移/初始化，已有库仅验证
.\Kimi版\demo.ps1 -Action Reset -Confirm
```

演示操作拒绝链接或重解析的数据库目录/文件，不会搜索和删除其他数据库。生产库升级、备份和真实账号初始化不属于这些脚本。

## 停止、日志与故障诊断

启动后只有一个持续运行的控制窗口，前后端输出重定向到日志。请保持控制窗口打开；优先按 **Ctrl+C** 停止。helper 在正常取消或启动/运行失败时，只清理本次由它创建的 Python/Node 进程。关闭窗口、强制结束 PowerShell 或机器断电的行为仍需 Windows 实机验收；不要用强制关闭窗口作为可靠停机方式。关闭浏览器不会停止服务。

每次运行在 `systems/pms-suite/logs/<版本>-<时间>-<启动进程PID>/` 创建独立目录，不覆盖上次日志：

- `startup.log`：版本、阶段、实际工作目录、子命令退出码及本次服务 PID。
- 各安装阶段的 `.log`：该次 pip/npm 的标准输出和错误。
- `后端-out.log`、`后端-error.log`、`前端-out.log`、`前端-error.log`：实际启动的服务输出。

失败提示包含版本、阶段和本次日志目录；子命令的正退出码 1–255 会向外保留，其他退出或启动检查失败返回 1。BAT 失败时暂停，便于读取信息。日志保留在本机，可能含本地路径和演示操作记录，请先检查、脱敏再分享，不上传环境文件、令牌或数据库。

| 提示 | 处理 |
| --- | --- |
| 未找到 Python/Node/npm 或版本检查失败 | 安装满足条件的运行时，重新打开终端后检查 PATH。 |
| 创建 venv / pip 安装失败 | 查看本次阶段日志，检查 Python venv/pip 支持、网络、证书与本机权限。修复原因后重跑；不要改源、关安全策略或复制旧 venv。 |
| npm ci 失败或锁文件缺失/不匹配 | 保留日志交依赖 owner 审核；不改成 npm install，不手工改锁绕过。 |
| 端口占用或已有启动任务 | 确认是否另一个启动窗口仍运行；由操作者正常关闭原服务后重试。脚本不结束占用端口的进程。 |
| 后端退出 / 健康检查超时 | 查看后端错误日志；确认使用本表健康地址，保留原演示库，不自动重置。 |
| 账号密码错误 | 核对 WP03 文档与版本地址，确认是自己的演示库；已有账号可能已改密，启动器不会覆盖密码。 |
| 本地环境配置或其他数据库配置被拒绝 | 保留原文件/变量，在独立干净源码目录与演示终端运行。 |
